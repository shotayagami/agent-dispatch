# エージェントに任せる判断の範囲（サンプル）

エージェントが人に確かめずに進めてよい範囲の決まりです。`agent-collaboration.md` と合わせて使います。

## 3 つの段階

| 段階 | 動き方 |
|---|---|
| ① 単独で実行 | 確かめずに実行する。報告は作業の最後にまとめてよい |
| ② 実行して報告 | 実行し、その Issue か PR にコメントで報告する |
| ③ 止まる | 実行しない。Issue に判断待ちのコメントを残し、通知を送る |

## 段階の決め方

影響範囲と、元に戻せるかの 2 つで決める。

| 影響範囲 | 戻せる | 戻せない |
|---|---|---|
| 作業域 | ① | ① |
| 共有物 | ② | ③ |
| 本番 | サービスの動作を変えなければ ②、変えるなら ③ | ③ |

- 作業域: 自分の worktree、一時ディレクトリ、push する前の自分のブランチ
- 共有物: リモートのブランチ・Issue・PR、各リポジトリ本体の作業ツリー、他の人やエージェントも使う設定
- 本番: 稼働中のサービスと、マージ後に本番へ反映される変更。反映の経路（自動同期するパス、デプロイする CI、配布するスクリプトなど）を自分の環境で洗い出して書く
- 戻せない: 削除、上書き、外部への送信、資格情報の変更のように、実行前の状態に戻す手段がない操作。戻し方を具体的に書けない操作も戻せない側に入れる

影響範囲や戻せるかを判定できないときは、厳しい側の段階にする。

## 個別の決まり

- PR のマージ: 本番への反映経路に入らない変更だけを含み、CI が成功している PR は ②。それ以外と、判定できない PR は ③。
- 外部への送信: 下書きの作成は ①、自分宛ての通知と書式の決まった運用通知は ②、それ以外の送信は ③。
- 読み取り: 影響範囲によらず ①。ただし `.env`、鍵、トークンのファイルは中身を表示せず、必要な行だけを grep で取り出す。
- 安全判定やサンドボックスに拒否された操作: 表で ① や ② にあたっても ③ とする。コマンドの分割や言い換えで再試行しない。

## ② の報告

その Issue か PR に、何をしたか、なぜ必要だったか、どう戻すかをコメントで書く。

## ③ で止まるとき

1. Issue に次の形でコメントを残す。

   ```markdown
   ## 判断待ち
   - 操作:
   - 必要な理由:
   - 選択肢: (推奨に「推奨」と付ける)
   - 実行するときに測り直すこと:
   - 待つ間に進める作業:
   ```

2. 通知を送る（`bin/agent-notify`）。
3. 判断を待つ操作に依存しない作業は続ける。依存する作業には手を付けない。
4. 人の回答は同じ Issue のコメントで受け取る。実行するときは、回答の時点ではなく実行の時点の状態で判断する。

対話中のセッションでは、Issue と通知の代わりに、その場で利用者に選択肢を示して尋ねる。
